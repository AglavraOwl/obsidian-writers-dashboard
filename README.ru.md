# Writer's Dashboard

[English](README.md)

Доска на основе Canvas для организации коротких рассказов. Рассказ — это заметка с frontmatter; блок кода `storycard` в этой заметке рендерит её как живую карточку — как в самой заметке, так и автоматически внутри узла (file-node) Canvas, который на неё ссылается.

Работаете с этим хранилищем вместе с ИИ-агентом (Claude Code или аналогом)? См. [`AGENTS.md`](AGENTS.md) — там полная схема frontmatter и процесс превращения папки рассказа в карточку по запросу вроде «сделай карточку рассказа из этой папки».

## Создание карточки

Запустите команду **«Create story card»** из Command Palette (использует папку текущей открытой заметки, либо по умолчанию создаёт seed, если ничего не открыто), либо кликните правой кнопкой по папке в проводнике файлов → **«New story card»**.

Переключатель **«This is a seed»** — это тип карточки, а не статус: seed — это только заголовок, краткое описание идеи и focus; у полноценного рассказа дополнительно есть статус, цель (target), цель по словам/символам и части (parts). Переключение сразу показывает/скрывает эти поля. Seed сохраняется в папку, заданную в Settings → Writer's Dashboard → «Seeds folder» (можно выбрать существующую или создать новую на месте) вместо той папки, откуда запущена команда; на карточке-seed не показывается счётчик слов/символов; и у seed нет собственного статуса — `status` нужен только для того, как вы отслеживаете рассказ, когда он уже реально пишется (по умолчанию «in progress» / «done», полностью настраивается в Settings).

Кнопка **«+ Add part from this folder (incl. subfolders)»** открывает выбор из остальных markdown-файлов этой папки — включая файлы во вложенных папках вроде «Drafts» или «materials» — так что имена файлов никогда не вводятся вручную. Создаёт файл `_card — <title>.md` и открывает его.

**Перевод seed в рассказ:** нажмите кнопку ↗ на карточке-seed, либо запустите команду **«Promote seed to story»**. Позволяет создать новую папку (по умолчанию предлагается соседняя с папкой Seeds, названная по заголовку) либо выбрать существующую, переносит карточку туда через встроенный механизм переименования Obsidian — который обновляет ссылки, в том числе на dashboard canvas, — выключает `is_seed` и открывает форму редактирования, чтобы сразу заполнить статус/target/parts.

**Редактирование карточки:** нажмите на кнопку ✎ прямо на карточке, либо запустите команду **«Edit story card»**, когда заметка-карточка открыта. Та же форма, предзаполненная — можно добавить цель, изменить target, добавить или убрать части, не трогая сырой YAML.

Панель Properties скрывается у любой заметки с `cssclasses: [storyboard-card]` (это именно те заметки, которые создаёт плагин), так как карточка уже показывает эти данные — переключается в Settings → Writer's Dashboard → «Hide frontmatter on story cards». Изменения статуса рассказа/части происходят через элементы управления самой отрендеренной карточки, а не через прямое редактирование YAML.

**Важно:** поле «highlight / priority» есть в схеме данных, но его интерфейс (★ на карточке и переключатель в этой форме) сейчас отключён — Obsidian Canvas ненадёжно перерисовывает встроенный контент заметок в реальном времени, из-за чего звёздочка выглядела кликабельной, но ничего не происходило до перезагрузки. См. `ROADMAP.md`.

## Шаблон карточки (ручной способ / для продвинутых)

Запустите команду **«Insert story card template»** в пустой заметке, либо скопируйте это:

````yaml
---
storyboard-card: true
cssclasses:
  - storyboard-card
title: ""
description: ""
is_seed: true
status: ""
highlight: false
target: ""
word_goal:
char_goal:
focus: []
final_draft: ""
parts: []
---

```storycard
```
````

- `is_seed` — тип карточки, а не статус. `true` = только идея (показываются title/description/focus; status, target, цели и parts игнорируются, даже если заполнены). `false` = рассказ в работе.
- `status` — имеет значение только при `is_seed: false`; один из настроенных статусов рассказа (Settings → Writer's Dashboard). Цвет определяется позицией в этом списке, а не названием.
- `description` — одна-две строки, показываются под заголовком на карточке.
- `highlight` — есть в схеме, но его интерфейс сейчас отключён (см. примечание выше).
- `target` — свободный текст, вручную; меняется, когда меняется реальная цель.
- `word_goal` / `char_goal` — опционально. Если задано, карточка показывает прогресс-бар; если оба поля пустые, просто показывается текущий итог.
- `focus` — список следующих шагов, а не один: можно держать несколько актуальных вариантов одновременно (например, «отредактировать главу 1» и «написать главу 2») и выбирать по настроению. Показывается и для seed, и для полноценного рассказа. Обычная строка тоже работает, если задача одна.
- `final_draft` — ссылка на заметку со сведённым финальным текстом; показывается на карточке, когда заполнена.
- `parts` — список `{file, status}`, один файл на часть. Статус каждой части тоже берётся из настроенного списка и получает свою цветную точку. Количество слов считается по актуальному содержимому файлов, а не вводится вручную.

## Команды

- **Insert story card template** — вставляет YAML + блок выше в текущую заметку.
- **Sync dashboard canvas with story cards** — сканирует хранилище на заметки с `storyboard-card: true` и добавляет отсутствующие как file-node'ы на canvas, заданный в Settings → Writer's Dashboard → «Dashboard canvas», размещая их сеткой ниже уже существующего содержимого. Никогда не перемещает и не удаляет существующие узлы — их расположение после этого остаётся на ваше усмотрение.
- **Create story card** / **Edit story card** / **Promote seed to story** — см. выше.

## Один dashboard canvas, а не несколько

Плагин рассчитан на **один** canvas, на котором живут все карточки рассказов — а не на отдельный canvas для каждого рассказа. Canvas для одного конкретного рассказа (план сцен, карта сюжета) — это совершенно нормально иметь, но это другой тип canvas, и его не стоит также назначать «Dashboard canvas» — если назначить, «Sync» выгрузит туда же все карточки из всего хранилища.

Dashboard canvas выбирается из выпадающего списка существующих `.canvas`-файлов в Settings → Writer's Dashboard, с кнопкой «+ New canvas» для создания нового на месте. Смена выбранного canvas теперь требует подтверждения и объясняет последствия: уже размещённые на старом canvas карточки никуда не переносятся — просто новые синхронизации пойдут на новый, так что при переключении туда-обратно оба canvas могут разойтись между собой.

## Циклы / группировка

Не является функцией плагина — используйте обычный Canvas: разместите на доске заметку для цикла и проведите стрелку от неё к каждой карточке рассказа. Карточки рассказов — это обычные file-node'ы, так что связи работают точно так же, как и для любого другого узла canvas.

## Разработка

```bash
npm install
npm run dev    # сборка с watch
npm run build  # продакшен-сборка
```

После сборки перезагрузите Obsidian (либо выключите/включите плагин), затем включите «Writer's Dashboard» в Settings → Community plugins.
